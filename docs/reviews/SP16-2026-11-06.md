## Implementation

- Reuse error classification, jitter and current retry counts. Support numeric/fractional/HTTP-date Retry-After, including zero. A requested wait exceeding the remaining budget stops instead of retrying before the provider permits it.
- The explicit elapsed envelope is 240 seconds, derived from the existing three-attempt policy's two capped 120-second waits. It starts on the first failure, includes subsequent provider execution and backoff, and is monotonic. The first request keeps its existing watchdog. No new policy configuration/default, provider route or model fallback was introduced. Permanent auth does not activate fallback; existing credential refresh remains intact.
- Scope the budget outside provider arguments. Both existing transport watchdogs close their owned request client when a retry reaches its deadline. Streaming workers capture their budget/retirement fence so late workers cannot borrow a replacement call's cleared scope or dispatch another request. Existing immediate fresh-connection recovery remains immediate and now publishes structured retry status/checks cancellation.
- Backoff checks Stop every 50 ms and fences dispatch after waiting. Partial visible text on an exception is preserved and not replayed. No tool retry or accepted-submission replay was added.
- A readable `RetryStatus` carries reason class, attempt, delay, observed time, elapsed budget and absolute next-attempt/budget deadlines. The web retry-only callback persists an idempotent `retry.status` session event before publication, with root-run/turn ownership checks. A versioned projection uses the existing string status/recovery seam, without a migration or controller edit. Legacy runtime consumers retain readable text.
- Emit a transition and 30-second liveness observations, never a per-second backend countdown. Liveness reuses the original absolute deadlines and one durable event per retry attempt. This also avoids the existing 45-second web stall threshold during a legitimate long backoff.
- StatusPill computes the countdown locally; RecoveryCard also decodes the projection so wire metadata is not product copy. Expired/invalid data asks for backend status, and a restart without a live authoritative turn never restores a fabricated countdown.

No SP15 timing hooks, timing_summary, outcome metadata, SessionDB migrations, controllers, dependencies, lockfiles, generated manifests or web_dist changes are in this packet. No PLAN checkbox, issue closure, merge or release.
