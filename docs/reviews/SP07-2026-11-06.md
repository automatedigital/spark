## Implementation contract

`GET /api/sessions/{session}/tool-results/{call}?paged=true` returns one page of at most 65,536 raw UTF-8 bytes, with byte offset, next_offset, total_bytes, truncated, revision and full raw SHA-256. A trailing partial codepoint is deferred to the next page; arbitrary non-boundary offsets fail. Continuations require the revision. The default compatibility request preserves its existing complete sanitized string and fields, now dispatched off the event loop.

The isolated read adapter opens a worker-owned `mode=ro` SQLite connection and read transaction, reusing existing SessionDB lineage methods through a read-only facade without constructing/migrating SessionDB. Its message SQL selects only row identity, name and NULL status, limited to one owned result. Incremental SQLite blob reads never request more than 64 KiB; no full thread/content value is projected into Python on the paged path. Raw stored text is unchanged. Content hashing scans the selected result in bounded chunks on each read: this intentionally trades O(result bytes) work for revision validation without a schema owner/change. There is no generic cache or transport.

Revision hashes bind active profile path, resolved owning session, row identity and raw bytes. Every page/download chunk re-resolves ownership and checks revision. Missing/wrong-thread results return 404; another profile cannot use the original revision. A changed result yields 409 before a new response; a mid-download change terminates the stream. Content-Length plus SHA-256 verification prevents the browser adopting a partial/mixed download.

`GET .../download?revision=...` uses existing dashboard authentication middleware and streams exact stored UTF-8 bytes, with Content-Length and X-Content-SHA256. The explicit browser action verifies length/hash before saving. It may allocate a full Blob only after that user action; preview/copy never does.

ToolCallBubble owns native cancellation and fences connection generation, result identity, collapse and unmount. Expanding uses the dedicated paged domain client; explicit Next page replaces the displayed page instead of growing the DOM. Copy preview copies only visible content. Media detection stays below the existing 12,000-character threshold; path detection is capped to that prefix and 20 attachments; rendered arguments and inline result previews are bounded. A failed revision can be retried by closing/reopening.
