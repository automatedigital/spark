## Implementation and scope

Optional trailing `AbortSignal` arguments preserve existing defaults for session
list/detail/history/search/forks, model reads, recovery and related conversation
read methods. `fetchJSON` preserves AbortError during error-body consumption.
Connection/credential setters publish an epoch change without retaining secrets.

`ReadOwner` captures backend, connection/auth epoch, profile epoch and the existing
view-owner predicate. Every read receives a distinct controller. Retirement,
profile replacement and connection changes abort outstanding reads; resolve and
reject both recheck identity, including transports that disregard cancellation.
Cleanup removes only that read's registration. Existing view/session generation
checks remain around state updates and finally blocks.

The actual session controller uses this lifetime for SP02 recovery snapshots,
forks metadata, latest history, delayed tail reconciliation, pagination and exact
content. Stream completion's existing history callback reaches this same owner.
SP02 still consumes one authoritative recovery response, including compression
lineage; cancellation adds no alternate snapshot, cache, deduplication or replay.
Pagination's error/finally writes are fenced and new navigation resets its loading
flag. Retired transcript reads cannot schedule persisted detail writes.

POST/PATCH/PUT/DELETE paths, accepted submissions, warm-session mutations and
SP01 durable receipt/retry behavior receive no owner signal. Existing SP11,
SP12, SP19, SP20 and SP21 clients may retain native AbortControllers and pass
signals directly through fetchJSON; this helper is optional, not a new global
controller or data layer. SP05 caching/deduplication stays separate.

No backend implementation, DB lifetime/schema, PromptBar, skills-context,
McpSection, tool-result functions, lockfile, manifest or packaged web_dist change
is included. SP07 head `dd136b9a` was inspected: its tool-result API functions
remain outside these hunks and must be preserved during later integration.

The existing chat-contracts fork fixture now seeds real SQLite fork history
instead of mocking only the obsolete separate messages read. All behavioral
assertions remain; the SP02 recovery route now sees the same durable fork result.
