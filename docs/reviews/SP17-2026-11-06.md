## Change and contracts

- A shared validator admits string and structured schedules for preview, creation, updates and due-job dispatch. Nonpositive/noninteger/overflow intervals, unknown kinds, malformed timestamps/cron expressions and invalid IANA zones fail explicitly. Updates cannot replace job IDs.
- Optional per-job timezone is stored inside the existing schedule object. Jobs without it retain configured/server cron semantics and the existing system-local interpretation of legacy naive timestamps. UTC arithmetic keeps interval durations elapsed-time based across DST. Cron skips gap wall times and runs overlapping wall times once; naive zoned one-shots reject gaps and select the first fold.
- Invalid stored schedules/timestamps are quarantined under the existing thread/process mutation lock: paused, disabled, no next run, repair reason. Unchanged quarantined records are not rewritten every tick. Existing atomic storage, cross-process locks and unrelated job fields remain in place.
- POST `/api/cron/preview` returns up to five absolute ISO occurrences, explicit effective timezone, missed-run/DST policy and configuration readiness for model/provider/skills/delivery. It creates no job, resolves no execution credential, contacts no provider, and sends no delivery.
- Preview deliberately avoids `resolve_runtime_provider`: that execution resolver may refresh OAuth, seed/select pools or fetch local model metadata. It reuses canonical explicit provider resolution, named custom-provider lookup and registry metadata. Auto/OAuth credential usability remains **unknown**, visibly labelled, rather than inventing an authenticated/live result. SP10 integration must retain that read-only contract.
- Dedicated domain client/types and a debounced, abortable standalone preview support create/edit forms. Errors are readable, retryable and fenced on retirement. One-shots/intervals reopen from stored canonical fields rather than unparseable display labels. Paused repair reasons and saved timezone are visible.
- Existing missed-run behavior is stated explicitly: recurring catch-up once within half a period clamped to 120 seconds–2 hours, otherwise skip; saved due one-shots execute on restart, missing next times recover only within 120 seconds. Recurring work advances before execution; existing uncertain one-shot retry behavior is disclosed. No SP18 attempt ledger/history was added.
