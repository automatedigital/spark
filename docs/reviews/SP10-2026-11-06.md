## Implementation

`GET /api/providers/catalogue` projects registered runtime metadata, with the
existing generic OpenRouter/custom routes and the existing custom-provider
compatibility view. It does not call a provider resolver, probe an endpoint,
refresh OAuth, import an optional SDK, or query models.dev. Stable runtime IDs
and registration labels replace Settings' mirrored provider/options/key/default
maps. Selecting a provider preserves the user's model and endpoint; defaults
are placeholders rather than implicit migrations.

Credential presence describes only the active profile's `.env` or saved custom
configuration. Inherited environment credentials and external OAuth stores are
not adopted by this read. No credential values or custom endpoint URLs enter
the response. Availability and model-specific tools/vision/reasoning remain
explicitly `unknown`: configured credentials do not establish usability or model
support. Optional SDK absence does not make metadata enumeration fail.

Settings model discovery is an explicit Refresh action, so opening/selecting a
provider does not trigger live model enumeration. Typed model IDs remain valid. Discovery state remounts on provider/endpoint changes
so a prior selection cannot leave a live-results label under the new route.
The dedicated domain client uses existing auth/connection transport, no cache,
and rejects responses from a retired connection generation. Settings retains
SP09's draft provider and lazy entry/content boundaries.

`ModelPicker.tsx` consumes the catalogue for the configured provider label and
availability while retaining typed IDs and existing conversation model choices.
**Integration limit:** this prepared checkout has no callers of `ModelPicker`.
Its active ChatPanel model controls were excluded from this packet's ownership;
this PR does not claim to have changed that separate live picker. SP02 integration
must retain or deliberately wire the component contract. No active-thread toolset,
system prefix, provider resolver or routing classifier was changed.
