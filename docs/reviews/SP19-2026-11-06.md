## Implemented locally

A terminal-specific lifecycle helper binds creation acknowledgements and stream
callbacks to a mounted owner and restart generation. Retired/superseded created
runs receive one Stop request for their exact ID. Reconnect retains the run ID
and attaches its stream; it never creates a process. Automatic reattachment is
limited to two retries (500 ms and 1000 ms), then displays disconnected with an
explicit Reconnect action. Restart is the sole explicit new-process action.
Timers/streams retire together; stale callbacks cannot replace current state.
Input error callbacks and the initial resize timer also respect retirement.

Seven focused tests cover deferred acknowledgement after repeated retirement,
reverse restart acknowledgement order, replacement project survival, bounded
stream loss/reattachment, stale stream callbacks/timer cancellation, synchronous
reattachment failure and uncertain start failure without automatic creation retry.

## Reproduction and blocking process boundary

The browser fixture imports the real rendered terminal component through Vite,
uses an isolated temporary HOME/SPARK_HOME with two projects, and delays only the
start acknowledgement after the real backend has created a PTY. It writes the
shell's actual `$$` PID to a project-local marker file. No provider/account calls
are required. It checks process existence independently of UI state and cleans
its owned processes in finally, using SIGKILL only as test teardown.

Matched baseline/candidate process flows on this machine:

- Baseline component from the exact base, same fixture, one run/two real shells:
  deferred alpha start, unmount, bravo replacement, reverse acknowledgement
  release. Baseline reproduced an orphan (PID 70871); replacement PID 70873.
- Candidate, one final run/two real shells: alpha PID 72672, bravo PID 72674.
  Exactly one Stop call targeted `wterm_a5ee7642cac94ceb` (alpha). The actual
  response was `{ok:true,run_id:"wterm_a5ee7642cac94ceb",status:"stopped"}`.
  Nevertheless alpha remained alive throughout the 30-second cleanup deadline.
  The fixture failed with `Timed out: retired shell process cleanup`.

The backend `stop_terminal_run` in `workspace_routes.py` marks a run stopped and
sends SIGTERM to the interactive shell's process group. Interactive zsh ignores
that signal in this fixture; the route reports stopped without confirming process
exit. The backend also returns queued creation before process startup, so its
stop-before-process-adoption behavior deserves a backend-owner regression test.
No backend changes were made because the assigned ownership expressly excludes
that file. Do not accept the UI-only stop call as proof of shell cleanup.

The browser stops at the first failed process assertion. Browser-level stream
loss/reconnect, reverse restarts and final close assertions exist later in the
fixture but were NOT reached; their unit coverage is not browser acceptance.
Do not publish this packet until the backend owner provides confirmed cleanup,
including queued-start retirement, and the complete fixture passes.

## Limits, integration and rollback

Windows native PTY support is explicitly unavailable in the current backend;
Windows and installed macOS packages were not tested. SP04 integration remains a
later compatibility check. Backend/profile switching outside terminal owner
retirement is not claimed validated. A lost creation acknowledgement with no run
ID remains uncertain, with no automatic creation retry.

To unblock, the workspace-route owner must make Stop effective for interactive
shells and queued starts without falsely reporting confirmed process completion.
Then rerun the packet fixture in full plus lint/all frontend tests/build and
multi-chat/recovery before the single publication push and stacked PR.

Rollback: revert the scoped implementation commit; no schema/data migration or
user-state restoration is necessary. Retire/stop active terminals before rolling
back. Local useful work is committed; publication is withheld under the explicit
prepublication gate. Leave issue #206 and the SP19 checkbox open.
