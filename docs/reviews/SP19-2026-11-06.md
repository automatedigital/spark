## Confirmed process fix

Previously Stop marked `stopped` before sending SIGTERM and never confirmed exit.
Interactive zsh ignored SIGTERM in the real-process browser fixture. Queued workers
could also start after Stop because process creation/adoption was not fenced.

Each existing run now owns a lifecycle lock and a revoked-start flag. Creation and
process adoption serialize with Stop; Stop either revokes a queued launch or waits
for the exact in-flight launch to be adopted before terminating it. Command runs
also create an exclusive POSIX session/group. Worker reaping uses the same lock,
so escalation retains the unreaped leader PID rather than risking a reused PID.
Running events are emitted inside that ownership boundary.

POSIX Stop validates group ownership, sends TERM, waits 500 ms, sends KILL to the
owned group and reaps the leader with a two-second bound. An exited shell may leave
children holding the PTY; Darwin can hide that unreaped leader from getpgid, so the
still-reserved leader PID remains the group fence. Darwin can also return EPERM
when signalling an already exited group; that case is accepted only after the
leader's exit is independently confirmed. Other termination failures return HTTP
500 and do not set a successful stopped state. The caller's group is rejected.

Seven backend regressions cover TERM-resistant process/group escalation,
replacement survival, queued command and shell revocation, failed Stop, launch
adoption racing Stop, caller-group rejection, and an exited leader with a surviving
background child. Existing terminal route tests exercise real command output and
interactive input.

## Limits and handoff

Interactive PTYs remain explicitly unsupported on Windows. Windows command Stop
terminates/reaps its direct process; native Windows process-tree parity and
installed Windows/macOS packages were not tested. POSIX process groups cannot
contain descendants that deliberately create separate sessions; this is not a
new generic process manager. Lost creation acknowledgements without an ID remain
uncertain. SP04 transport compatibility remains a later integration check.
