## Delivered behavior

- The existing ContextCompressor exposes a preflight and an explicit
  `safe_boundary` option on its existing `compress` entry point. Its existing
  head/tail boundaries, provider summary function and typed checkpoint builder
  are reused. Automatic compression behavior is unchanged.
- Explicit compaction first run-length encodes repeated old tool-output lines,
  preserving each distinct line, repetition count and JSON status/metadata.
  A deterministic reduction of at least 20% avoids a paid summary. Otherwise,
  only eligible older assistant prose can be summarized. System/user messages,
  structured attachments/reasoning, decisions, pending questions and complete
  tool pairs remain protected. Unique tool output is not truncated.
- Summary input is limited to 32,000 estimated tokens; output is capped at
  4,000 tokens (or the lower engine cap). The caller waits at most 20 seconds.
  At most two abandoned/in-flight summary calls can exist. Late provider results
  operate on an isolated compressor and cannot commit or mutate a live agent.
  Provider dollar cost is unknown; these are token/time limits, not a price quote.
  A failed, timed-out, oversized or ineffective summary keeps original context
  and the last checkpoint. No Dream, memory flush/reload, smart role routing,
  live prefix/toolset rebuild or second agent is introduced.
- The context-only API reserves the existing active-turn registry before its
  first await. Existing Send rejects the reservation. The continuation ID is
  reserved before lineage commits, covering the rollover interval too. A
  disconnected HTTP waiter cannot release ownership while its worker continues.
  Active roots, live children, pending decisions, incomplete pairs and stale
  transcript revisions prevent compaction; revision and durable idle state are
  checked again inside the persistence transaction.
- Success atomically stores a compression continuation, source checkpoint,
  copied brief/context items/frozen schema epochs and lineage/reduction event.
  Original messages and system prefix stay intact. The checkpoint belongs to
  its source session; the continuation has a complete compact transcript. This
  deliberately avoids the existing typed-resume fallback replacing protected
  continuation rows with a shortened tail. Failed writes roll back through the
  existing SessionDB transaction owner; no migration/schema changes.
- ContextWindowMeter/PromptBar show history, tools, instructions, memory and
  attachments, explicit estimate/unknown labels, preflight limits, an idle
  compact action and before/after feedback. Component counts refresh after
  success. The estimate endpoint includes history even when the caller omits
  history_message_count, using SQL length aggregation rather than materializing
  the entire transcript for each composer estimate.

No ChatPanel, read controller, shared API barrel, agent preparation/cache/DB
lifetime helper, config, dependency, lockfile, manifest or generated bundle is
part of the implementation. The build's generated web_dist was cleaned/restored.
