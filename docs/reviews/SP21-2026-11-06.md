MemoryPage owns one abortable Markdown read feeding both editable cards. It
retains the existing Settings draft owner. Mutation failures are inline, preserve
edits/additions, and can be retried. Refresh failures retain the previous data and
drafts. Edits explain the next supported conversation/compaction boundary; Forget
explicitly targets only that Markdown file. Saving an edit retains its original
entry identity even if a refresh changes list positions.

The dedicated domain client uses existing fetchJSON, AbortSignal and existing
profile/connection generations. It rejects late results after cancellation or
scope changes. There is no generic cache, shared API barrel edit, or SP05 adoption
claim. SP04/SP05 integration remains a parent acceptance gate.

## Read safety and limits

The adapter imports no memory provider, SDK, retrieval engine or Dream runtime.
It resolves the active profile on each request, honors the existing holographic
plugin's configured DB path only within that profile, opens SQLite with `mode=ro`
and `query_only`, and never calls the constructor that creates/migrates/recovers
stores. Missing and unavailable/unsupported stores have separate explicit states.
Old facts tables with fact_id/content remain readable; absent source/category/time
are null and rendered as unknown. Stored values are shown without inferred
provenance. Optional external providers are explicitly outside this local view.

Facts use a parameterized literal case-insensitive substring query, monotonically
increasing fact IDs, default 20/max 50 results and one lookahead row. Only projected
text columns are selected, never vectors, all facts or a provider's full-store
load. Search input is capped at 200 characters, IDs fit SQLite signed integers,
text at 16,384 characters per fact (with a visible truncation notice), metadata
at 512 characters and SQLite values at 1 MiB. A progress handler stops queries
after at most approximately two million VM instructions; busy/oversized stores
return unavailable without repair. This is browsing order, not retrieval ranking.
A large store scan can reach this budget and report unavailable rather than
complete an expensive exhaustive search. SQLite lower() retains its normal
Unicode/case-folding limitations.

Dream lists only actual .md files under the active profile's workspace/wiki/dreams,
excluding index.md. Enumeration is capped at 1,000 directory entries, pages at 20,
and review reads at 65,536 characters. Traversal and symlink escape are rejected.
No review or source is synthesized. Reviews and facts render as React text,
including literal HTML/script payloads. No implicit Dream, extraction, forgetting,
retrieval counters or ranking changes are introduced.
