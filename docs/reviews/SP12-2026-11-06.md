## Source and implementation

The base `CommandPalette.tsx` calls `Promise.allSettled` with projects, 500
sessions, jobs and skills on every mount/open, then separately searches message
text. Its project endpoint also recursively counts files. H3 was reviewed at
Hermes commit `90d6b98fd86d20981ee06ddd5b7d93e4320f26a4` (`tools/session_search_tool.py`):
bounded targeted recall is the relevant concept. No Hermes code was copied.

The palette now renders the existing static destinations immediately. One
palette-owned recent snapshot (12 threads, 60-second freshness, backend/auth/
profile epoch scoped) survives dialog unmount; a cold resolved profile makes
one recent request. Unresolved profile identity does not initiate a read.
Typing is retained when that identity resolves. Explicit queries debounce 150 ms
and independently request threads, messages, projects, jobs and skills. Each
category returns at most 12 rows and a next offset; paging replaces that category's
visible page so the menu stays bounded. Category failure retains other results.

A new dedicated client uses existing `fetchJSON` and AbortSignal. Open/query
ownership and backend/auth/profile generations fence success, failure, cache
adoption and finally/loading updates. Close/unmount/query/scope retirement aborts
owned requests. Selection uses a destination identity rather than an array index,
and keyboard selection scrolls into view. Existing global navigation target kinds
and page IDs are retained; message matches still open their thread (no SP13 jump).

The new synchronous FastAPI domain router runs reads in the worker pool, opens
and closes its own SessionDB handle, reuses existing recent/FTS APIs and adds a
read-only parameterized title/ID projection over the existing sessions table.
No SessionDB/schema edits or search database. Projects only inspect root entries;
no recursive file counting. Existing cron/skill metadata discovery is used only
for explicit queries; no opening-time enumeration, sync/install or LLM call.
The server change is only a lazy import/registration seam. Existing endpoints,
controllers, ChatPanel, Settings/MCP, shared API barrels/types, config, manifests,
lockfiles and tracked production bundle are unchanged.

SP04 transport-owner adoption and SP05 reference-resource adoption remain later
integration gates. The palette-specific recent snapshot is not a shared resource
cache. Query-time skill/job discovery still scans the existing domain metadata;
this packet bounds responses, not those domains' underlying discovery work.

Event-to-first-option uses the browser clock and a MutationObserver. Cold includes
lazy chunk loading/Suspense; warm follows closing and reopening in the same
context. Query-to-visible is separately measured, includes debounce and automation,
and targets the oldest thread beyond the previous 500-row window. Completed
category request durations are also emitted in the candidate JSON. Response bytes
are decoded successful open-time response bodies, not compressed wire bytes.

All five candidate opens used `/api/palette/recent?…limit=12…`, with no opening

open. Host load varied substantially (observed load averages up to 206 while

causal benchmark. No memory/installed-package performance claim is made.
