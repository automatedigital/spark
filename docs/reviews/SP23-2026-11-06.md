## Implemented

- Dedicated child module uses the MCP SDK's stdio and Streamable HTTP clients, initializes a session, follows bounded tool-list pagination (100 pages / 10,000 tools), validates input schemas, and exits transport/session contexts. It does not call the CLI probe or the process-global MCP loop. Stdio command/environment resolution and malware checks are reused only inside the isolated child.
- Configuration is delivered over stdin, capped at 64 KiB. Child SDK stdout/stderr and server logs are discarded. Only a validated, at-most-4-KiB result containing an allowlisted error code and tool count is accepted. Parent measures duration itself. No raw exceptions, URLs, headers, env, descriptions, or commands enter admin output.
- Dedicated owner has two workers and eight total outstanding admissions. Concurrent same-profile/name/revision requests reuse one admin run. Excess requests receive 429. Saved edits/removal retire old records and cancel their work; late success is fenced into cancelled. Each worker captures its owning profile. Completed admin metadata is bounded to 64 retained entries, and repeat tests retire the preceding terminal run.
- Child SDK work has a 12-second deadline; the parent bounds the entire child lifetime to 15 seconds plus bounded process discovery/reaping. POSIX descendant discovery includes SDK stdio children with independent process groups; cleanup kills owned descendants and the probe group. Platforms without this cleanup capability fail explicitly. If the one-second `ps` preflight fails, no probe is launched.
- GET is passive. Configuration is projected as saved/configured plus unknown/testing/ready/failed readiness, last completed test time, elapsed duration, count, safe reason, and existing admin-run ID. Results are memory-only: restart means unknown. Configuration values are intentionally omitted from list/create responses. MCP request validation also omits rejected credential values.
- MCP Settings uses one initial passive list read. Test/Retry is explicit, polls only admitted active tests, displays safe errors/tool count/time/admin run ID, and invalidates displayed verification immediately after saving. Header configuration now survives the settings save adapter. SettingsPanelContent changes are confined to McpSection and necessary imports; provider/model functions are retained.

## Limits and rollback

Readiness is a point-in-time discovery test, not a guarantee of future tool execution. OAuth authorization is explicitly unsupported by this noninteractive test; it never opens a login or calls a model. Older SDKs without the required HTTP client report unavailable. Non-POSIX cleanup is explicitly unsupported until platform-specific process ownership is implemented and tested. SP05 adoption remains an integration follow-up, not a second resource cache here.

Rollback the MCP route/helper/UI commits after allowing admitted children to terminate within their bounded lifetime. No config schema, session database, active conversation toolsets, or persisted user data migration is involved. Do not restore the unsafe CLI-output test path as a security fix.
