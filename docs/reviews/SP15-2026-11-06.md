## Behavior and field contract

Existing per-root `turn_id` outcome JSON now has optional `timing_summary`.
Existing latest/all-outcome and authoritative recovery reads carry it unchanged.
The chat passes its latest confirmed outcome into the existing SessionInfoBar;
no extra client fetch, controller rewrite or new request/prefix is introduced.
The disclosure stays collapsed initially and supports missing usage.

Shape (seconds are nonnegative numbers or null):

```typescript
{
  version: 1,
  clock: 'server_monotonic',
  accepted: boolean,
  seconds: {
    preparation: number | null,
    queue: number | null,
    provider_start: number | null,
    first_token: number | null,
    accepted_to_first_token: number | null,
    tools: number | null,
    finish: number | null
  },
  tool_count: number,
  usage: null | { prompt_tokens?: number, output_tokens?: number,
    cache_read_tokens?: number, cache_write_tokens?: number,
    reasoning_tokens?: number },
  provider?: string, model?: string, role?: string,
  routing_reason?: string,
  routing_decision?: {
    role?: string, desired_role?: string, reason?: string,
    signals?: Record<string, number | boolean>, scores?: Record<string, number>
  }
}
```

SP24 contract: `timing_summary.routing_decision` and `.routing_reason` come only
from the actual selected `turn_route` when present. Decision scalar fields and
bounded numeric/boolean signals/scores preserve the current routing decision;
there is no classifier, fabricated reason, credential or transcript. Missing
fields remain absent. Provider/model/role identify the selected route.

Accepted starts at root registration after durable command acceptance, rather
than browser send time. Preparation ends before execution submission; queue is
execution executor wait. Provider start observes entry into the existing provider
transport method (including local transport setup, not a remote receipt). First
token observes the first nonempty text delta callback; first status/reasoning/tool
is never substituted. Tool duration reuses the existing monotonic tool callbacks
and sums completed durations, which may overlap. Finish is authoritative root
finalization before outcome persistence; it excludes the final outcome write and
workspace after-scan. Stages overlap and are not a stacked total. No browser/server
clock subtraction occurs. Browser render delay remains unmeasured and explicitly
separate. Existing stream/checkpoint writes are unchanged; diagnostics add no
per-token DB write and keep only seven marks, one aggregate and bounded metadata.

Provider usage reuses only new efficiency rows for this invocation, with
`usage_source == provider`; session totals and estimates are not presented as
this turn's reported usage. Unavailable/incomplete counters stay unknown. If the
bounded 500-row recorder rolls over the starting index, usage can be unknown;
there is no invented zero. Transport method wrappers are restored on success
and failure and forward the same request arguments.
