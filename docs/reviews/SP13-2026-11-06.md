## Result and boundaries

Palette message actions carry their stable message ID independently of the
thread destination. A scoped pending anchor survives shell target consumption
until the selected panel mounts, and cannot cross backend/profile/auth epochs.
Ordinary thread navigation clears a pending anchor.

A dedicated read helper/router validates the requested message against the
active profile's resolved compression family. It reads a consistent SQLite
snapshot and materializes at most 200 messages, with a normal client page of 50.
The `(timestamp, id)` keyset cursors are validated against the stored historical
session. No entire transcript hydration, index migration or FTS change is used.
Compression ancestors remain readable historical contexts; deleted/unavailable
anchors explicitly show the nearest latest saved context, without matching by
snippet. Invalid/deleted cursors return an honest conflict requiring reopening.

The bounded history viewport is read-only and separate from the live transcript.
It scrolls/focuses/highlights the exact message, supports older/newer replacement
pages, and returns to the independently updated live tail. Hidden live timeline
controls are inert/hidden while browsing. This deliberately preserves SP06's
shared timeline projection, virtualizer and scroll functions, and SP14's context
controls; ChatPanel changes only integrate the anchor view and visibility/focus.
The original live transcript is neither replaced with an incomplete middle window
nor merged across an unrepresented historical gap.
